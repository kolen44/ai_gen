# Synthetic Character Pipeline

Пайплайн синтетического персонажа с удержанием личности: фотопак в разных образах и видео из
кадра, с замером времени и стоимости на каждой генерации и с собственным safety-слоем.

Управляется из веб-админки: карточка персонажа, списки промптов, выбор пайплайна и параметров,
запуск и просмотр результатов — всё оттуда. Промпты живут только в админке; ни один скрипт не
подмешивает свой текст и не подставляет свой вместо пустого списка.

---

## Два пути генерации

| | своя карта (RunPod) | flaq.ai | fal.ai |
|---|---|---|---|
| фото | SDXL-финетюн на арендованной GPU | Seedream v5.0 Pro | — |
| видео | Wan2.2-I2V-A14B | Wan 3.0, Seedance, Flux, MiniMax | Kling, Hailuo |
| контентных ограничений | нет | нет | **есть, жёсткие** |
| ролик 5 с | 24.1 мин · $0.64 | **156 с · $0.45** | 207 с |
| стоимость | по секундам аренды | $0.09/с ролика на 720p | по тарифу |

**Провайдер выбирается не по цене, а по тому, что вообще получится сгенерировать.** Kling через
fal.ai отклоняет обнажённый кадр на ВХОДЕ: `HTTP 422 content_policy_violation` — ролик из
портретного кадра прошёл, из кадра `scene_15.png` (nsfw 0.9983) отклонён. flaq тот же кадр
принимает. Замерено на выходе, а не на входе:

```
исходный кадр scene_15.png     nsfw 0.9983
кадр   0   nsfw 0.9983   лицо к эталону 0.795
кадр  75   nsfw 0.9997   лицо к эталону 0.677
кадр 149   nsfw 0.9996   лицо к эталону 0.686
среднее    nsfw 0.9993   лицо 0.714
```

Ролик остаётся NSFW до последнего кадра, а не только в первом. Поэтому умолчание облачного
пути — **Wan 3.0 у flaq** (`pipeline/flaq_video.py`), и провайдер определяется по имени модели:
у flaq оно всегда с суффиксом `-image-to-video`.

Своя карта остаётся нужной там, где важны воспроизводимость, свои веса и цена за длинный ролик:
на flaq считается посекундно, и минута видео стоит уже дороже часа аренды A100.

## Архитектура

Слои разделены по одному принципу: чем ниже слой, тем меньше он знает о том, кто его вызвал.

```
admin/                 веб-интерфейс: карточка персонажа, промпты, параметры, запуск, результаты
  app.py               Flask: маршруты + RunTracker (отвязанный процесс прогона, лог в файле)
  runpod_pods.py       жизненный цикл пода: создать, залить код, дождаться, забрать файлы, удалить
        │
        ▼ запускает как отдельный процесс
scripts/               сценарии прогона — «дирижёры», сами ничего не считают
  pod_full_run.py      полный прогон на своей карте: пак -> образы -> видео -> доводка -> отчёт
  admin_checkup.py     113 проверок: маршруты, проводка интерфейса, совпадение умолчаний
  safety_demo.py       прогон реального промпта и кадра через safety-слой
        │
        ├──────────────► своя карта: HTTP к воркеру на поде
        │                runpod_worker/   FastAPI: очередь, персонажи, метрики, эндпоинты
        │                  service.py     склейка запроса и генератора, safety на каждом кадре
        │                       │
        │                       ▼
        │                worker/          вся вычислительная часть, ничего не знает про HTTP
        │                  config.py          чекпойнты, режимы фиксации лица, видеомодели
        │                  photo_generation.py ModelManager + генератор, длинные промпты, VRAM
        │                  video_generation.py менеджер видеомоделей, ускоряющая LoRA, зум
        │                  face_detailer.py    второй проход по лицу
        │                  hires.py            апскейл-проход
        │                  video_enhance.py    покадровая доводка лица в ролике
        │                  identity.py         InsightFace: эмбеддинг и возраст — одна загрузка
        │
        └──────────────► облако: pipeline/run_pipeline.py -> flaq_client / fal_video

pipeline/prompt_config.py   ЕДИНСТВЕННЫЙ источник промптов и настроек: читает .env админки
safety/moderation_pipeline.py  гейты: промпт, NSFW, возраст, watchlist
```

Три правила, которые держат эту схему:

1. **Промпт собирается только из полей админки.** Проверяется чекапом: в `scripts/` не должно
   быть зашитых шаблонов, а пустой список в админке означает пропуск этапа, а не подстановку
   своего текста.
2. **`worker/` не знает про HTTP, а `runpod_worker/` не считает.** Поэтому вычислительную часть
   можно запустить локально и в тесте, не поднимая сервис.
3. **Настройки читаются в одной точке.** `SafetyPipeline` берёт пороги из `.env` сам; вызывающий
   код их не передаёт и не может незаметно разойтись с админкой.

### Workflow — код, а не ComfyUI-граф

Граф не используется намеренно. Пайплайну нужны вещи, которые в ноде не выражаются: отбор
лучшего из нескольких попыток по замеренной метрике, ветвление по свободной VRAM, повторные
попытки с разными seed, запись времени и стоимости на каждую генерацию, и главное — сборка
промпта из полей админки. Всё это обычный управляющий код, и держать его в графе означало бы
писать его же внутри нод, потеряв тесты и историю изменений.

Обратная сторона честная: готовые ComfyUI-воркфлоу из сообщества сюда не переносятся, каждый
приём приходится реализовывать самому.

## Модели и параметры

### Фото — своя карта

| | значение |
|---|---|
| чекпойнт | `John6666/lustify-sdxl-nsfwsfw-v2-sdxl` (SDXL-финетюн, без контентных ограничений) |
| сэмплер | DPM++ 2M Karras (`DPMSolverMultistepScheduler`, `use_karras_sigmas=True`) |
| шагов | 40 |
| разрешение | 1024×1536, после hires ×1.5 → 1536×2304 |
| попыток на кадр | 2, оставляется лучшая по косинусу лица |
| фиксация лица | двухэтапная: сцена без FaceID, лицо вживляет детейлер вторым проходом |
| детейлер | SDXL + IP-Adapter FaceID, порог включения — лицо мельче 320 px |

Режимы фиксации лица (`worker/config.py::IDENTITY_MODES`) — три, значения по умолчанию
замерены, а не взяты из документации:

| режим | веса | scale | референсов |
|---|---|---|---|
| `base` | `ip-adapter-faceid_sdxl.bin` | 0.95 | 1 |
| `portrait` | `ip-adapter-faceid-portrait_sdxl.bin` | 0.85 | 1 |
| `plusv2` | `ip-adapter-faceid-plusv2_sdxl.bin` + LoRA | 0.70 | 1 |

`portrait` официально принимает несколько референсов, но на замере несколько эталонов давали
**хуже**, чем один, — поэтому по умолчанию один.

### Видео — своя карта

| | значение |
|---|---|
| модель | `Wan-AI/Wan2.2-I2V-A14B-Diffusers` (MoE: эксперт высокого и низкого шума) |
| разрешение | 1280×720, 81 кадр |
| шагов | 40 (полное качество) или 4 (с ускоряющей LoRA) |
| guidance | 3.5 на полном, 1.0 с LoRA |
| размещение | CPU-оффлоад обязателен: 63 GB весов не помещаются рядом с вниманием даже на 80 GB |

**Ускоряющая LoRA — LightX2V** (`rzgar/Wan2.2_LightX2V_4Step_Uncensored`, Apache-2.0):

```
high: Wan2.2_LightX2V_high_n54vv.safetensors   -> transformer   (ранние шаги)
low:  Wan2.2_LightX2V_low_n54vv.safetensors    -> transformer_2 (поздние шаги)
веса адаптеров 1.0 / 1.0, шагов 4, guidance 1.0
```

LoRA две, по одной на эксперта, и грузятся они в разные трансформеры — одна на оба означала бы
чужие веса в чужом эксперте. CFG отключается: дистилляция обучена работать без него, а
guidance > 1 на четырёх шагах даёт пережжённую картинку.

Разница не в «настройках», а в числе шагов: **61.5 минуты против 13.2** на одном и том же
исходнике. За 40 шагов модель успевает проработать то, что за 4 остаётся приблизительным.
Выбирается в админке полем «качество видео», по умолчанию — полное.

### Seed

Один базовый seed на персонажа, всё остальное — детерминированные производные
(`worker/seed_manager.py`, `scripts/pod_full_run.py`):

```
эталон лица      = base_seed
кадр образа i    = base_seed + 1000·i + 37·попытка
кадр под видео   = base_seed + 9000 + 100·номер_ролика
первый кадр видео= seed того кадра, из которого ролик делается
движение в видео = frame_seed + 500000
```

Шаг 1000 между кадрами — чтобы композиция не повторялась. Шаг 37 между попытками одного кадра —
чтобы попытки отличались, иначе отбор лучшей бессмыслен. Отдельный `motion_seed` нужен потому,
что первый кадр и траектория движения сэмплируются независимо: один и тот же кадр можно оживить
по-разному, не трогая саму картинку.

Личность от seed **не зависит** — её держит эмбеддинг лица и второй проход детейлера. Поэтому
seed можно менять свободно ради разнообразия, не рискуя консистентностью.

| на одну генерацию | ~41 с | половина от кадра: попыток две |

| этап | штук | среднее | разброс | стоимость |
|---|---|---|---|---|

Видео у flaq считается по секундам готового ролика, и цена известна точно: $0.045/с на 480p,

```bash

```

Свежие цифры любого прогона на своей карте лежат в `run.json` (`totals`) и в `REPORT.md` рядом с
результатами — они считаются во время прогона, а не восстанавливаются потом по логам.

## Safety-слой

Четыре гейта. Первый — до генерации, остальные — по каждому готовому кадру и по выборке кадров
ролика. Живая демонстрация со свежими числами: `python scripts/safety_demo.py`, вывод —
[deliverables/SAFETY_DEMO_OUTPUT.txt](deliverables/SAFETY_DEMO_OUTPUT.txt).

### 1. Гейт промпта — до первой потраченной GPU-секунды

Регулярные выражения по запрещённой тематике плюс отдельный разбор числового возраста: `12 y/o`
блокируется по **значению**, а не по факту совпадения с шаблоном.

```
[ЗАБЛОКИРОВАН] 16 years old girl in school uniform   -> school|uniform, numeric_age=16
[ЗАБЛОКИРОВАН] teen model on the beach, nude          -> teen(ager)?
[ЗАБЛОКИРОВАН] photo of a 12 year old child           -> child(ren)?, numeric_age=12
[ЗАБЛОКИРОВАН] underage looking petite girl           -> underage
[ПРОПУЩЕН]     nude woman, 30 years old, natural light
```

Последняя строка — суть настройки: явная нагота у взрослого человека не блокируется, это целевой
контент. Блокируется несовершеннолетие.

### 2. NSFW-классификатор кадра

`Falconsai/nsfw_image_detection` (ViT, apache-2.0), self-hosted. Порог — `NSFW_THRESHOLD` из
админки. Замерено на реальных кадрах проекта:

```
кадр из образов (look_01.png)   nsfw_score = 0.9998   метка «nsfw»
эталонный портрет (01.png)      nsfw_score = 0.0005   метка «normal»
```

Порог 1.0 означает «пропускать всё», и это осознанный выбор: оценка всё равно считается и
попадает в отчёт по каждому кадру. Гейт здесь — измеритель и ручка, а не запрет.

### 3. Возраст по лицу

InsightFace `buffalo_l` (`genderage.onnx`) — тот же экземпляр, что считает ArcFace-эмбеддинг для
фиксации личности, одна загрузка на процесс. Отклоняется всё, что выглядит моложе
`MIN_ALLOWED_AGE`. На кадрах проекта: 35.0 и 30.0 лет при пороге 18.

Кадр, на котором лицо не найдено, не «проскакивает» молча — такой результат помечается отдельно.

### 4. Watchlist — сходство с реальным человеком

ArcFace-эмбеддинг кадра сверяется с галереей фото людей, на которых персонаж быть похож не
должен. Порог 0.5 по косинусу — с запасом: одно лицо ArcFace обычно даёт выше 0.6, чужие в этом
проекте измерены до 0.387 (`scripts/calibrate_similarity.py`). Проверка живая, а не декларация:

```
лицо есть в галерее          max cosine = 1.000  -> ЗАБЛОКИРОВАН
другой кадр того же человека max cosine = 0.756  -> ЗАБЛОКИРОВАН
```

Эмбеддинги галереи считаются один раз и кешируются рядом с папкой.

### Где это вызывается

| гейт | когда |
|---|---|
| промпт | перед каждой генерацией |
| NSFW, возраст, watchlist | после каждого готового кадра, одним отчётом |
| кадры видео | выборкой по ролику, а не только первый кадр |

Вердикт по каждому кадру пишется в `run.json` (`nsfw_score`, `estimated_age`, `safety_allowed`),
то есть решение гейта проверяется постфактум по любому кадру.

Границы честные: это self-hosted проверки против ограниченного списка, а не промышленная
модерация. Возраст — оценка по лицу, а не документ.

## Запуск

```bash
python admin/app.py                  # админка на http://127.0.0.1:5000
python scripts/admin_checkup.py      # 113 проверок целостности, перед прогоном
python scripts/safety_demo.py        # safety-слой на реальных данных
```

Прогон на своей карте запускается из админки (создать под → дождаться развёртывания → «Запустить»)
либо напрямую:

```bash
python scripts/pod_full_run.py --pod <id> --frames 8 --videos 1
```

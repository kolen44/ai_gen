# Safety-слой

Три независимые проверки, все self-hosted, работают на том же поде, где идёт генерация — без
внешних платных API. Код — `safety/moderation_pipeline.py`.

## 1. PromptGate — до генерации

Regex/keyword deny-list на текст промпта: возрастные термины (child, teen, minor, school
girl/uniform и т.д.) плюс отдельная числовая проверка возраста (например, "16 years old"
блокируется, "30 years old" — нет: блокирует именно значение ниже порога, а не сам факт упоминания
числа). Блокирует генерацию до того, как потрачена GPU-секунда — самый дешёвый момент для отказа.

Реально протестировано (без GPU, чистая логика): `python safety/moderation_pipeline.py`
```
'adult woman, 30 years old, studio portrait...'  -> allowed=True
'16 years old girl in school uniform'            -> allowed=False  matched=[school/uniform, numeric_age=16]
'teen model on the beach'                        -> allowed=False  matched=[teen]
```

## 2. ImageSafetyGate — NSFW-классификация после генерации

Модель: `Falconsai/nsfw_image_detection` (ViT, apache-2.0, self-hosted через `transformers`).
Каждое фото и каждый N-й кадр видео (по умолчанию каждый 5-й — при 24fps и 5 секундах это ~24
проверки на клип) прогоняются через классификатор; при `nsfw_score` выше порога результат
помечается как не прошедший gate.

**Реально протестировано на GPU** (не только код-ревью — модель реально скачана и вызвана):
```
ImageSafetyGate real run OK
allowed: True  label: normal  score: 0.00064
```

Важно: NSFW сам по себе — это классификатор контента, не индикатор возраста. Блокирует он или
только логирует NSFW — зависит от профиля продукта (SFW vs WetDreams-профиль, см.
REQUIREMENTS_FROM_USER.md, п.3); в обоих профилях он работает одинаково, меняется только то, что
происходит при срабатывании.

## 3. IdentitySafetyGate — возраст и похожесть на реальных людей после генерации

Использует InsightFace (`buffalo_l`) — ту же модель, что даёт face embedding для IP-Adapter
FaceID при генерации (общий загрузчик — `worker/identity.py`, модель грузится на под один раз).

- **Возраст.** Атрибут age, который InsightFace уже считает по лицу. Порог с запасом от заявленного
  в character bible возраста персонажа (например, если персонаж "выглядит на 30" — порог отказа
  ниже, скажем 25). Это эвристика по внешности на фото, не юридическое доказательство возраста —
  финальный гейт перед публикацией всегда ручной визуальный ревью.
- **Похожесть на реальных людей.** Cosine similarity ArcFace-эмбеддинга сгенерированного лица
  против галереи эмбеддингов watchlist (публичные фигуры / конкретные лица от заказчика, если
  список предоставлен — см. REQUIREMENTS_FROM_USER.md, п.5). Порог 0.5 — консервативный: реальное
  совпадение обычно даёт >0.6-0.7, но лучше ложно отклонить и пересмотреть руками, чем пропустить.

**Честное ограничение, а не скрытое:** полной проверки "не похож ни на одного живого человека"
не существует технически — self-hosted инструментами можно свериться только с конкретным
watchlist, не со всеми людьми на Земле. Снижение риска на входе: эталонное лицо генерируется из
текстового промпта в чистом латентном шуме (`Stage 0`, txt2img, без img2img/морфинга с реального
фото) — то есть совпадение с реальным лицом может быть только случайным, не унаследованным от
исходника.

**Реально прогнано на арендованном поде на всех 8 фото + референсе + 25 кадрах видео** (не
демо на одном тестовом изображении): каждое фото и каждый проверенный кадр видео получили
реальную оценку возраста (диапазон 25–57 по 8 фото, все выше порога 25) и реальную cosine
similarity против watchlist (watchlist не был предоставлен на этот прогон, поэтому
similarity-часть гейта в этой сессии не блокировала ничего — гейт технически отработал на всех
кадрах, просто сравнивать было не с кем, см. REQUIREMENTS_FROM_USER.md п.5). Полные значения —
`benchmarking/benchmark_log.csv`.

**Реальная находка и фикс (не гипотеза):** `onnxruntime-gpu`, поставленный с PyPI по умолчанию
(версии ≥1.27), собран под CUDA 13, а драйвер арендованного пода — под CUDA 12.4 → InsightFace
откатывался на `CPUExecutionProvider` вместо GPU (функционально верно, но на видео с его 25
проверяемыми кадрами это добавляло несколько минут вместо секунд). Исправлено на втором прогоне:
`onnxruntime-gpu<1.27` (собран под CUDA 12) + `LD_LIBRARY_PATH`, указывающий на cuDNN-библиотеки
из pip-пакета `nvidia-cudnn-cu12` (иначе даже правильная версия onnxruntime-gpu не находит
`libcudnn.so.9`). После фикса — реальный `CUDAExecutionProvider`, подтверждено в логе. Второй
эффект той же находки: video-пайплайн (LTX-Video) занимает почти весь VRAM 24GB-карты, из-за чего
InsightFace не может выделить собственный CUDA-контекст сразу после генерации видео
(`CUBLAS failure: resource allocation failed`) — исправлено переносом видео-пайплайна на CPU
(`pipeline.to("cpu")` + `torch.cuda.empty_cache()`) перед покадровой safety-проверкой. Оба фикса
задокументированы в `deploy/runpod_setup.md` и `worker/video_generation.py`.

## Итог по обеим частям задания

| Проверка | Что ловит | Блокирует или логирует |
|---|---|---|
| PromptGate | запрещённые термины в тексте промпта | блокирует до генерации |
| ImageSafetyGate | NSFW-контент | блокирует (SFW-профиль) / логирует (WetDreams-профиль) |
| IdentitySafetyGate — возраст | лицо выглядит младше порога | блокирует |
| IdentitySafetyGate — похожесть | совпадение с лицом из watchlist | блокирует |

Всё выполняется автоматически внутри `worker/photo_generation.py` (`PhotoGenerator.generate()`) и
`worker/video_generation.py` (`VideoGenerator.generate()`) — результат каждой проверки попадает в
`PhotoGenerationResult`/`VideoGenerationResult` (`nsfw_score`, `estimated_age`,
`watchlist_similarity`, `safety_allowed`) и в строку `benchmark_log.csv`, ничего не нужно вызывать
отдельно вручную после генерации.
